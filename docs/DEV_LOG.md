## 2. 架构决策记录（ADR）

### ADR-001 转码放云端，端内不做 FFmpeg/WASM
- 端内单包 2MB/总分包 30MB、WASM 仅包内路径、无多线程/大内存保证 → 端内只做导入/播放/参数/进度。

### ADR-002 服务端主方案：独立微信云托管（路线 B）
- 云开发内的云托管已停更；新项目用独立微信云托管。Docker 可装 FFmpeg、支持 0.25核0.5G~16核32G、缩容 0、callContainer 免域名。
- 状态：作为路线 B 兜底；用户要求先验证路线 A。

### ADR-003 异步任务 + 轮询（修正“同步转码”）
- `callContainer` timeout 上限 15s，服务端请求 60s（待实测）→ 任务入队 + 客户端轮询；不能同步长请求。

### ADR-004 导入仅“会话文件 + 录音”
- 小程序不能读手机本地文件；`chooseMessageFile` 2.5.0+ / 录音 ≤10min；首页引导文件传输助手。

### ADR-005 输出收敛 mp3/m4a/wav，flac/ogg 设高级
- iOS InnerAudioContext 不支持 flac/ogg/amr/ape/wma；默认三格式双端可试听。

### ADR-006 导出：转发/PC 保存/临时链接
- `saveFileToDisk` 仅 PC；`openDocument` 不支持音频；手机端无公共目录写入；临时链接按 2h 申请（云托管对象存储默认 24h）。

### ADR-007 内容安全：mediaCheckAsync + 消息推送
- 音频 ≤10MB、支持 mp3/aac/ac3/wma/flac/vorbis/opus/wav；30min 自适应 32k 代理；创建任务时并行送检；risky 删除 + 阻断导出；窗口期策略用户已确认。

### ADR-008 任务状态用 JSON，不引入 MySQL（MVP）
- 任务 JSON 存云存储/对象存储；单 worker；额度计数 `quotas/{openid}/{date}.json` + 进程内互斥；任务 24h 过期、JSON 48h；量上来再换 Redis/MySQL。

### ADR-009 清理：生命周期 + 定时/顺带清理
- 输出 24h；输入转码后删；优先存储生命周期规则，否则建任务顺带 + 外部定时 `/internal/cleanup`。

### ADR-010 免费策略
- 用户决策：公开发布、完全免费、无广告、无付费墙；个人主体不可虚拟支付；MVP 每日 5 次限额。

### ADR-011 小程序 AI 开发模式不进 MVP
- 官方 AI 能力内测、暂不可提审；仅远期记录。

### ADR-012 工程迁移
- 删除 quickstart 示例页/云函数；重建 `miniprogram/pages`、`utils`、`components`；新增 `server/`（B）或云函数（A）。

### ADR-013 上传票据与归属校验
- 客户端拿不到 openid，不能用 `in/{openid}/`；服务端 `POST /v1/upload-tickets` 下发绑定 openid 的 cloudPath，`POST /v1/tasks` 校验 ticket/fileID/openid；对象存储尽量仅创建者可读写；防 IDOR。

### ADR-014 额度计数与任务超时补偿
- 计数 JSON + 进程内互斥（单实例）；GET/POST 惰性判定 `updatedAt>5min` → FAILED/TIMEOUT；任务 JSON 含 `leaseAt/attempts`。

### ADR-015 技术路线先验云函数、云托管兜底（用户决策）
- M2a 验证云开发云函数 + 静态 FFmpeg；通过则 MVP 不引入云托管；失败再上 B（M2b）。

### ADR-016 个人主体 + 启用云开发环境
- 个人主体、公开发布、免费；云开发环境已开通并写入 envList.js/app.js；路线 A 验证使用该环境。
- 影响：不可虚拟支付；可备案/发布工具类；内容安全/隐私按个人主体要求。

### ADR-017 在线音乐编辑：云端 FFmpeg 渲染 + 端内近似预览 + 两段式导出（2026-10-28）
- 编辑模型非破坏 EditPlan（源 + 片段 + 效果 + 配乐），导出时才编译为 FFmpeg filtergraph；见 [MUSIC_EDITOR_DESIGN](./MUSIC_EDITOR_DESIGN.md) ADR-E01～E11。
- 波形由服务端生成 peaks（50ms 桶/int8/base64，10min≈32KB），不做端内整首解码（内存 200MB+）。
- 预览用 InnerAudioContext 顺序播放 + 音量渐变近似；UI 明示「近似预览，以导出为准」。
- 导出因官方 `callFunction` 无客户端 timeout、切后台 5s 中断，改为 `createEditTask`（快）→ `runEditTask`（执行）→ `getEditTask`（轮询/恢复）两段式，`clientToken`/`taskId` 幂等。
- 限额：编辑源/成片 ≤10min、源文件 ≤50MB、输出 ≤50MB（WAV ≤4min）；额度沿用 `QUOTA_ENFORCED` 开关（测试期不限次数）。
- 1 CPU 实测 10min 最坏组合 22.7s；P1 可选「数据库事件触发器」后台化（仅按量付费环境支持，待验证）。

### ADR-018 音乐剪辑 MVP 与格式转换合并为双入口（2026-10-28）
- 产品结构：同一微信小程序、同一 AppID/云环境下，`tabBar` 提供「格式转换 / 音乐剪辑」两个入口；首页增加剪辑入口卡，导航标题改「音频工具箱」。
- 实现取舍：先落同步 MVP（`analyzeAudio` + `renderEdit`，单文件多段、只出 mp3），不做 upload ticket/两段式任务/多源/BGM/多格式；设计文档 §19 记录偏差与后续 M9 迭代。
- 验证：devtools E2E 通过（4s WAV→分析→选区→删除→导出 2.4s/57.59KB），格式转换回归 SUCCESS，包体 123.2KB。
- 影响：v1.0 转换行为未变；剪辑与转换共用云函数与云环境，后续上线需补额度/内容安全/归属校验。

### ADR-019 多片段拼接 + 每片段缓入缓出（MVP v2，2026-10-28）
- 数据模型：sources[]（≤5 个源，每源分析/波形/本地路径）+ clips[]（≤40 片，sourceId/in/out/fadeIn/fadeOut）；clips 顺序即成片顺序，同一源可被多片引用（分割/删除选区）。
- 后端：`renderEdit` 按 sources/clips 走 v2；同源多片 `asplit`；每片 `atrim+asetpts` + 本片 `afade`（in st=0、out st=clipDur-fadeOut，concat 前）→ concat → 全局 volume + alimiter；旧 segments 请求保留 v1。
- 前端：多选导入、片段条（上移/下移/删除/分割/裁剪到选区/重置/删除选区/撤销）、每片 fade chips、跨源顺序预览、v2 导出；波形显示选中片段所属源，片段外灰化。
- 验证：2 源 3 片 E2E 导出 5.0s/118.82KB，RMS 包络验证顺序与每片淡入淡出；后端容器/mock 测试全绿；转换回归 SUCCESS。
- 限制：片段排序暂用按钮（无拖拽）、无缩放/横向滚动时间轴、无 BGM/变速/多格式/模板；两段式任务与 upload ticket 仍未做。
