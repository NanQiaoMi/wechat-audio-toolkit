# 音频格式转换小程序 - 任务规划与实施路线图

## 1. 项目概述与开发目标
本项目旨在打造一个基于**微信小程序原生开发** + **微信云开发 (Cloud Base)** 的多格式音频转换与处理工具。
用户可在微信中直接选取音频文件，完成 MP3、WAV、M4A、AAC、FLAC、OGG、AMR 等主流音频格式之间的互相转换，并支持试听、本地保存与好友分享。

## 3. 详细任务分解清单 (WBS)

### 阶段一：需求与技术方案设计（已完成）
- [x] **T1.1 产品需求规格说明书 (PRD)**：制定完整业务流程、格式支持矩阵、UI/UX 规范。
- [x] **T1.2 技术选型论证**：
  - 前端：微信原生框架（轻量高灵敏度，无框架冗余体积，适合工具类）。
  - 后端：微信云开发 Cloud Functions + FFmpeg 静态二进制（跨格式最全面、免运维服务器、天生鉴权）。
  - 本地快捷通路：对于单向 PCM/WAV 互转可保留本地拓展点。
- [x] **T1.3 文档建设**：建立 `PRD.md`、`TASK_PLAN.md`、`DEV_LOG.md`。

### 阶段二：转码云函数与核心引擎开发 (里程碑 1)
- [ ] **T2.1 云函数架构搭建 (`cloudfunctions/audioConvert`)**：
  - 初始化云函数目录与依赖环境 (`package.json`)。
  - 集成 Node.js 环境可执行的 static FFmpeg 引擎。
- [ ] **T2.2 转码核心执行逻辑**：
  - 接收参数：`fileID`（源音频在云存储的路径）、`targetFormat`（目标格式）、`options`（比特率、采样率、声道）。
  - 核心处理流：从云存储拉取临时文件至 `/tmp` -> 执行 FFmpeg 异步转码 -> 结果写回云存储临时目录。
  - 元数据抽取：使用 ffprobe 获取源与目标音频的精准时长、大小、声道数、比特率。
- [ ] **T2.3 异常拦截与自动清理机制**：
  - 格式不合规或转码超时（设置 30s 熔断保护）的安全拦截。
  - 清理 `/tmp` 目录下的中间产物，防止云函数实例冷启动与磁盘溢出。
  - 返回统一的规范化 JSON 协议响应。

### 阶段三：小程序前端核心交互与视觉设计 (里程碑 2)
- [ ] **T3.1 全局样式与现代工具类 UI 设计**：
  - 现代简洁卡片风格（符合微信 Design 规范，柔和圆角与高质感阴影）。
  - 响应式布局，适配各种屏幕尺寸与刘海屏安全区。
- [ ] **T3.2 文件导入模块**：
  - 接入 `wx.chooseMessageFile`，支持微信会话文件直接选择。
  - 文件格式智能探测与合法性校验（扩展名白名单检测）。
  - 解析展示文件名、图标徽章、大小信息。
- [ ] **T3.3 转换配置面板**：
  - 6种主流目标格式选项卡（MP3 / WAV / M4A / AAC / FLAC / OGG），支持快捷单选。
  - 高级转码设置卡片（抽屉式折叠展示）：
    - 音频质量（320k / 192k / 128k）。
    - 采样率（44.1kHz / 48kHz / 默认）。
    - 声道（立体声 / 单声道）。

### 阶段四：音频播放与全流程串联 (里程碑 3)
- [ ] **T4.1 双轨音频播放器组件**：
  - 基于 `wx.createInnerAudioContext` 封装高复用音频控制器。
  - 原音频试听控制（播放/暂停、拖动进度、当前时间/总时间）。
  - 转码完成后的新音频即时试听与音质比对。
- [ ] **T4.2 全流程状态机与转码交互**：
  - 状态流转管理：`空闲 -> 已选文件 -> 上传中 -> 云端转码中 -> 转换成功 -> 错误处理`。
  - 友好的 Loading 进度动效与转码倒计时提示。
- [ ] **T4.3 转换结果对比看板**：
  - 转换前后文件大小对比柱状/卡片，展示压缩百分比。
  - 音频详情标签展示（格式变动、采样率变动）。

### 阶段五：文件保存、分享与历史记录 (里程碑 4)
- [ ] **T5.1 结果文件导出能力**：
  - 微信好友分享：调用 `wx.shareFileMessage`，一键将生成的文件直接发送给好友或微信群。
  - 本地下载：调用 `wx.cloud.downloadFile` + `wx.openDocument` / `wx.saveFile` 实现持久存储。
  - 剪贴板工具：复制文件临时外链，便于 PC 电脑端快速下载。
- [ ] **T5.2 历史记录模块**：
  - 使用 `wx.setStorage` 建立本地转换流水库（上限 20 条防膨胀）。
  - 历史列表界面（时间、文件名、前后格式、文件大小）。
  - 支持快捷再次试听、重新分享与一键清空记录。

### 阶段六：性能优化、真机实测与发布 (里程碑 5)
- [ ] **T6.1 边界场景测试**：
  - 0 字节文件、超 50MB 超限文件测试。
  - 特殊字符文件名、无扩展名文件容错测试。
  - iOS 与 Android 真机兼容性实测（尤其是音频播放与文件分享 API 表现）。

## 4. 关键技术方案对比与选型决策

| 方案 | 优点 | 缺点 | 本项目选型结论 |
| :--- | :--- | :--- | :--- |
| **方案 A：纯前端 WebAssembly (ffmpeg.wasm)** | 无需云端服务器，无流量费，离线可用 | 1. 微信 WXWebAssembly 内存受限易崩溃<br>2. wasm 二进制包 > 20MB 严重超标<br>3. 手机端 CPU 算力发热严重，转换慢 | **不作为全格式方案**；仅用于简单极速小格式（如 WAV->MP3）备选 |
| **方案 B：云函数 + 容器/自建服务器** | 算力强大，无大小限制 | 需常驻服务器维护，成本较高，跨域与鉴权复杂 | 适合超大并发商用阶段，初中期阶段维护成本高 |
| **方案 C：微信原生云开发 (Cloud Functions + FFmpeg)** | 1. 原生免鉴权集成，开发效率极高<br>2. 支持主流全格式高保真转码<br>3. 按量计费甚至享受微信免费额度<br>4. 依托腾讯云对象存储分发加速 | 单个云函数运行超时限制（最长可设 60s），单文件限制在 50MB 最佳 | **确定为主技术路线 (首选推荐)** |
