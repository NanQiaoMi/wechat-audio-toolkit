## 2. 架构设计与技术决策记录 (ADR)

### ADR-001：转码核心架构决策
- **背景**：用户需要在小程序内将各种音乐格式（MP3/WAV/FLAC/AAC/OGG/M4A 等）互相转换。
- **候选方案**：
  1. 纯前端 Wasm (WebAssembly + ffmpeg.wasm)
  2. 独立自建后端转码服务器 (ECS + Docker + Node/Python)
  3. 微信云开发云函数 (Cloud Functions + Static FFmpeg binary)
- **评估考量**：
  - 微信小程序主包 2MB、分包 20MB 限制；`WXWebAssembly` 在移动端容易出现 128MB+ 内存超限杀进程。
  - 纯自建服务需要公网 IP、备案域名、SSL 证书以及微信登录凭据互通，前期启动成本与运维工作量偏大。
  - 微信云开发云函数具备天然微信登录凭据（`cloud.getWXContext()`）、无须公网域名鉴权配置、提供开箱即用的云存储及临时读写目录 `/tmp`。
- **决定**：
  - **核心方案采用微信云开发云函数 + FFmpeg 转码流水线**。
  - 50MB 以内的常规音乐文件可在 3~8 秒内完成转码，并一键利用云存储分发或微信直接分享。

### ADR-002：文件选择与系统兼容方案
- **背景**：小程序内无法像 PC 浏览器直接打开文件系统的绝对路径。
- **决定**：
  - 采用微信原生 API `wx.chooseMessageFile`，允许用户从当前微信与好友的聊天记录、文件传输助手、群聊下载的文件中快速拾取音频。
  - 扩展名过滤包含：`['mp3', 'wav', 'aac', 'm4a', 'flac', 'ogg', 'wma', 'amr']`。
  - 体积上限统一设为 50MB，并在前端进行预检查拦截，杜绝上传超时。

### ADR-003：音频预览与试听实现
- **背景**：用户在转换前和转换后希望即时对比听感。
- **决定**：
  - 前端采用 `wx.createInnerAudioContext()`。
  - 针对原生直接支持的格式（MP3/AAC/WAV/M4A）提供播放进度条与播放暂停控制。
  - 针对不能直接播放的原生外格式（如 FLAC/OGG），提供友好提示“当前格式需转码后支持播放”。
